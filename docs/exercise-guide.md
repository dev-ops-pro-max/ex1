# Core Lightning Exercise Guide — Step by Step

Work through Exercises 1–4 **in order**. Each exercise builds on the previous one.

All scripts are run from the repository root. All CLN commands use
`lightning-cli --lightning-dir=lab/nodes/<node>`. All Bitcoin Core commands use
`bitcoin-cli -rpcuser=clnrpc -rpcpassword=clrpcpass -rpcport=18443 -regtest`.

Save every important output into `records/exercise-N/` (the exercise scripts do
this automatically) and fill the matching table in `templates/snapshot.md`.

---

## 0. Start the lab (once)

```bash
# From the repo root:
bash scripts/start-lab.sh
```

What it does:
1. Starts `bitcoind` in regtest mode with RPC user `clnrpc` / pass `clrpcpass` on port 18443.
2. Starts three Core Lightning nodes: `alice` (port 9735), `bob` (9736), `carol` (9737), all in `lab/nodes/`.
3. Creates an on-chain deposit address for each node (`newaddr`) and mines 101 blocks to it so each node has a funded on-chain wallet.

Verify the lab is up:

```bash
lightning-cli --lightning-dir=lab/nodes/alice getinfo
lightning-cli --lightning-dir=lab/nodes/bob  getinfo
lightning-cli --lightning-dir=lab/nodes/carol getinfo
```

Each response includes the node `id` (public key) — copy these, you need them for peer connections.

Stop the lab when you are done for the day:

```bash
bash scripts/stop-lab.sh
```

## Exercise 1 — First Node Setup and Invoice Generation

**Goal:** Verify Alice is running and funded, then create a BOLT11 invoice for
50,000 satoshis, description `"Coffee Payment"`, expiry 1 hour (3600 seconds).

Run:

```bash
bash scripts/exercise-01.sh
```

What the script does (you can also type these manually):

```bash
# 1. Confirm the node is operational
lightning-cli --lightning-dir=lab/nodes/alice getinfo

# 2. Confirm the on-chain wallet is funded
lightning-cli --lightning-dir=lab/nodes/alice listfunds
# Look for outputs[].amount_msat >= 50000000000msat (50,000 sat = 50,000,000 msat)

# 3. Create the invoice (amount in msat, label, description, expiry seconds)
lightning-cli --lightning-dir=lab/nodes/alice invoice 50000000msat coffee-payment "Coffee Payment" 3600
# Save the bolt11 string — this is your invoice

# 4. Decode it to verify amount, description, expiry
lightning-cli --lightning-dir=lab/nodes/alice decodeinvoice <bolt11>

# 5. Proof the invoice was generated by your node
lightning-cli --lightning-dir=lab/nodes/alice listinvoices
# Find the entry with label "coffee-payment":
#   status == "unpaid"
#   amount_msat == 50000000msat
#   description == "Coffee Payment"
#   payee == your node id (from step 1)
```

### What to capture in `records/exercise-01/`

- `invoice.txt` — the raw BOLT11 string
- `decoded.txt` — output of `decodeinvoice`
- `listinvoices.txt` — output proving the invoice exists on your node

### Verification checklist

- [ ] `decodeinvoice` shows `num_satoshis` == 50000 (amount_msat == 50000000msat)
- [ ] `description` == `"Coffee Payment"`
- [ ] `expiry` == 3600 (1 hour)
- [ ] `listinvoices` contains the invoice with `status: unpaid` and `payee` equal to Alice's node id
- [ ] `listfunds` shows a funded on-chain wallet before invoicing

Fill in **Table 1** in `templates/snapshot.md`, then commit:

```bash

git commit -m "Exercise 1: node funded and Coffee Payment invoice generated"
```

## Exercise 2 — Peer Connection and Channel Establishment

**Goal:** Connect Alice and Bob, have Alice open a 500,000 satoshi channel to Bob,
and verify the channel is `CHANNELD_NORMAL` on both nodes.

Run:

```bash
bash scripts/exercise-02.sh
```

Commands:

```bash
# 1. Get node IDs
ALICE_ID=$(lightning-cli --lightning-dir=lab/nodes/alice getinfo | python3 -c 'import sys,json;print(json.load(sys.stdin)["id"])')
BOB_ID=$(lightning-cli --lightning-dir=lab/nodes/bob  getinfo | python3 -c 'import sys,json;print(json.load(sys.stdin)["id"])')

# 2. Connect Alice -> Bob
lightning-cli --lightning-dir=lab/nodes/alice connect "$BOB_ID@127.0.0.1:9736"

# 3. Alice opens a 500,000 sat channel to Bob
lightning-cli --lightning-dir=lab/nodes/alice fundchannel "$BOB_ID" 500000
# Note the funding_txid in the output

# 4. Confirm the funding transaction on-chain
bitcoin-cli -rpcuser=clnrpc -rpcpassword=clrpcpass -rpcport=18443 -regtest generatetoaddress 6 $(bitcoin-cli -rpcuser=clnrpc -rpcpassword=clrpcpass -rpcport=18443 -regtest getnewaddress)

# 5. Verify the channel on both nodes
lightning-cli --lightning-dir=lab/nodes/alice listchannels
lightning-cli --lightning-dir=lab/nodes/bob  listchannels
lightning-cli --lightning-dir=lab/nodes/alice listpeers
lightning-cli --lightning-dir=lab/nodes/bob  listpeers
```

### What to look for

- `listpeers` on Alice lists Bob as a connected peer (and vice versa).
- `listchannels` on both nodes shows one channel with:
  - `amount_msat` == 500000000msat (500,000 sat)
  - Alice side: `to_us_msat` ≈ 500000000msat, Bob side: `to_them_msat` ≈ 500000000msat (Alice funded it)
  - `state` == `CHANNELD_NORMAL` (it will be `CHANNELD_AWAITING_LOCKIN` until 6 blocks confirm)

### What to capture in `records/exercise-02/`

- `connect.txt` — peer connect output
- `fundchannel.txt` — channel open output (funding_txid)
- `listchannels-alice.txt` and `listchannels-bob.txt` — channel state on both nodes
- `listpeers-alice.txt`, `listpeers-bob.txt` — peer confirmation

Fill in **Table 2** in `templates/snapshot.md`, then commit:

```bash
git add .
git commit -m "Exercise 2: Alice-Bob peer connection and 500k channel established"
```

## Exercise 3 — Multi-Hop Payment Routing

**Goal:** Add Carol, connect Bob–Carol, open a 300,000 sat channel, have Carol
invoice 100,000 satoshis, and have Alice pay it through Bob.

Run:

```bash
bash scripts/exercise-03.sh
```

Commands:

```bash
# 1. Connect Bob -> Carol and open a 300,000 sat channel
CAROL_ID=$(lightning-cli --lightning-dir=lab/nodes/carol getinfo | python3 -c 'import sys,json;print(json.load(sys.stdin)["id"])')
lightning-cli --lightning-dir=lab/nodes/bob connect "$CAROL_ID@127.0.0.1:9737"
lightning-cli --lightning-dir=lab/nodes/bob fundchannel "$CAROL_ID" 300000

# 2. Confirm on-chain
bitcoin-cli -rpcuser=clnrpc -rpcpassword=clrpcpass -rpcport=18443 -regtest generatetoaddress 6 $(bitcoin-cli -rpcuser=clnrpc -rpcpassword=clrpcpass -rpcport=18443 -regtest getnewaddress)

# 3. Verify Bob->Carol channel is CHANNELD_NORMAL
lightning-cli --lightning-dir=lab/nodes/bob listchannels
lightning-cli --lightning-dir=lab/nodes/carol listchannels

# 4. Carol generates a 100,000 sat invoice
lightning-cli --lightning-dir=lab/nodes/carol invoice 100000000msat inv-ex3 "Payment from Alice via Bob" 3600
# Save the bolt11

# 5. Alice pays (routes Alice -> Bob -> Carol)
lightning-cli --lightning-dir=lab/nodes/alice pay <bolt11>

# 6. Verify
lightning-cli --lightning-dir=lab/nodes/alice   listpays        # status complete, preimage present
lightning-cli --lightning-dir=lab/nodes/carol   listinvoices    # inv-ex3 status paid
lightning-cli --lightning-dir=lab/nodes/alice   listchannels    # alice->bob local -100,000 sat (-fee)
lightning-cli --lightning-dir=lab/nodes/bob     listchannels    # bob->carol remote +100,000 sat (+routing fee)
lightning-cli --lightning-dir=lab/nodes/carol   listchannels    # bob->carol local +100,000 sat
```

### What to capture in `records/exercise-03/`

- `invoice-carol.txt` — Carol's BOLT11
- `pay-alice.txt` — Alice's `pay` output
- `listpays-alice.txt` — proof of payment with preimage
- `listinvoices-carol.txt` — invoice marked paid
- `listchannels-*.txt` — channel balances after payment

### Verification checklist

- [ ] Alice's `listpays` shows the payment `status: complete` with a `preimage`
- [ ] Carol's `listinvoices` shows `inv-ex3` as `paid`
- [ ] Alice→Bob channel: Alice's local balance decreased by 100,000 sat (+ fee)
- [ ] Bob→Carol channel: Bob's local decreased, Carol's remote increased by 100,000 sat; Bob collected a routing fee
- [ ] The payment traversed exactly one intermediate hop (Bob)

Fill in **Table 3** in `templates/snapshot.md`, then commit:

```bash
git add .
git commit -m "Exercise 3: 100k sat payment routed Alice -> Bob -> Carol"
```

## Exercise 4 — Circular Rebalancing

**Goal:** Open a Carol→Alice channel (400,000 sat), then have Alice pay herself
150,000 satoshis via the circle Alice → Bob → Carol → Alice, and observe the
liquidity shift.

Run:

```bash
bash scripts/exercise-04.sh
```

Commands:

```bash
# 1. Carol opens a 400,000 sat channel to Alice
lightning-cli --lightning-dir=lab/nodes/carol fundchannel "$ALICE_ID" 400000

# 2. Confirm on-chain
bitcoin-cli -rpcuser=clnrpc -rpcpassword=clrpcpass -rpcport=18443 -regtest generatetoaddress 6 $(bitcoin-cli -rpcuser=clnrpc -rpcpassword=clrpcpass -rpcport=18443 -regtest getnewaddress)

# 3. Verify all three channels are CHANNELD_NORMAL
lightning-cli --lightning-dir=lab/nodes/alice   listchannels
lightning-cli --lightning-dir=lab/nodes/bob     listchannels
lightning-cli --lightning-dir=lab/nodes/carol   listchannels

# 4. BEFORE snapshot: record balances now (fill Table 4 "before" in templates/snapshot.md)
#    alice->bob, bob->carol, carol->alice: local/remote balances on each node

# 5. Carol invoices Alice 150,000 sat (payee is Alice)
lightning-cli --lightning-dir=lab/nodes/carol invoice 150000000msat inv-ex4 "Circular rebalance Alice via Bob Carol" 3600
# Save the bolt11

# 6. Alice pays herself through the circle
lightning-cli --lightning-dir=lab/nodes/alice pay <bolt11>

# 7. Verify
lightning-cli --lightning-dir=lab/nodes/alice listpays      # status complete, preimage
lightning-cli --lightning-dir=lab/nodes/carol listinvoices   # inv-ex4 paid

# 8. AFTER snapshot: re-list channels and fill Table 4 "after"
lightning-cli --lightning-dir=lab/nodes/alice   listchannels
lightning-cli --lightning-dir=lab/nodes/bob     listchannels
lightning-cli --lightning-dir=lab/nodes/carol   listchannels
```

### Expected balance shift (Alice funded Alice→Bob; Bob funded Bob→Carol; Carol funded Carol→Alice)

| Channel | Before | After (circular payment of 150,000 sat) |
|---------|--------|-----------------------------------------|
| Alice→Bob | Alice local 500,000 | Alice local **−150,000** → 350,000 sat |
| Bob→Carol | Bob local 300,000 | Bob local **−150,000 (+fee)** |
| Carol→Alice | Carol local 400,000 | Carol local **−150,000**, Alice remote **+150,000** |

So Alice moved liquidity: she spent outbound capacity on Alice→Bob and gained
inbound capacity on Carol→Alice (her remote balance there grew). Record the
exact msat values you observe (`to_us_msat` / `to_them_msat`, divide by 1000
for satoshis) — small routing fees will appear on Bob's channels.

> Note on wording: some course write-ups describe the result from the channel's
> perspective ("outbound capacity increased on Alice→Bob"). The technically
> correct observation for this funding setup is the table above: Alice's *local*
> balance on Alice→Bob goes down and her *remote* balance on Carol→Alice goes up.
> Write down what your nodes actually show.

### What to capture in `records/exercise-04/`

- `before-alice.txt`, `before-bob.txt`, `before-carol.txt` — `listchannels` before the payment
- `invoice-carol.txt` — circular invoice BOLT11
- `pay-alice.txt` — Alice's self-payment output
- `listpays-alice.txt` — preimage proof
- `after-alice.txt`, `after-bob.txt`, `after-carol.txt` — `listchannels` after the payment

### Verification checklist

- [ ] Three channels exist, all `CHANNELD_NORMAL`: Alice→Bob, Bob→Carol, Carol→Alice
- [ ] Alice's `listpays` shows `status: complete` with `preimage`
- [ ] Carol's invoice `inv-ex4` shows `paid`
- [ ] Before/after snapshots recorded for all three channels
- [ ] Liquidity shift matches: Alice→Bob local down 150,000 sat; Carol→Alice Alice-side (remote) up 150,000 sat

Fill in **Table 4** in `templates/snapshot.md`, then commit:

```bash
git add .
git commit -m "Exercise 4: circular rebalance 150k sat Alice -> Bob -> Carol -> Alice"
```
